# Design System Working Rules

- Always read the existing design system documentation before making changes.
- Preserve previously approved rules unless I explicitly request a modification.
- Do not reinterpret approved numeric values.
- Do not overwrite previous approved versions unless explicitly instructed.
- When creating a new version, preserve the previous version and create the next version separately.
- Documentation must use Markdown.
- Main design rules should be written in English.
- Add Korean explanations below each major section.
- Keep terminology, formatting, and naming consistent.
- Do not introduce new design tokens or components without instruction.
- Prefer reusable rules over project-specific rules.
- Base Design System rules and Theme rules must remain separate.
- Project-specific brand values must not modify the Base Design System.
- Use semantic token naming where possible.

**한국어 설명**

변경 전에 기존 디자인 시스템 문서를 읽고, 명시적으로 변경을 요청받지 않은 승인 규칙과 수치는 그대로 유지합니다. 이전 승인 버전을 덮어쓰지 않고 새 버전을 별도로 작성합니다. 문서는 Markdown으로 작성하며, 주요 규칙은 영어로 쓰고 각 주요 섹션 아래에 한국어 설명을 추가합니다. 용어, 형식, 이름을 일관되게 유지하고, 지시 없이 새 디자인 토큰이나 컴포넌트를 도입하지 않습니다. 프로젝트별 규칙보다 재사용 가능한 규칙을 우선하며, Base Design System과 Theme 규칙을 분리합니다. 프로젝트별 브랜드 값은 Base Design System을 변경하지 않으며, 가능한 경우 의미 기반 토큰 이름을 사용합니다.

## Versioning Rules

When creating a new version:

1. Read the latest existing version.
2. Preserve all approved rules.
3. Apply only newly approved changes.
4. Save the result as the next version.
5. Keep the previous version unchanged.

Current version:

`Base Design System v0.2`
